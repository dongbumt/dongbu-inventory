# ERP 개인 로그인 유지

- 신규 로그인은 서버 시각 기준 24시간 유지합니다.
- 로그인한 사용자가 데이터를 등록·수정·삭제하여 서버 트랜잭션이 성공하면, 저장 시점부터 다시 24시간 유지합니다.
- 조회, 새로고침, 5초 자동갱신, 권한 확인, 저장 오류와 충돌, 변경 없는 재시도는 연장하지 않습니다.
- 같은 계정이라도 다른 PC나 탭의 별도 세션을 함께 연장하지 않습니다. 만료되거나 로그아웃한 세션은 되살리지 않습니다.
- 배포 시 아직 유효한 기존 세션은 최초 로그인 시점부터 24시간으로 전환합니다. 만료된 세션은 제외합니다.
- 브라우저 저장 방식은 기존 `sessionStorage`를 유지합니다. 창·탭을 닫고 다시 열 때의 로그인 복원 동작은 브라우저 설정에 따릅니다.
- 라벨전용 PIN, 배송기사·모바일 관리자 전용 로그인은 별도 인증이므로 이 정책의 대상이 아닙니다.

## 서버 처리

`dbmt_erp_session_user`와 `dbmt_erp_has_permission`은 기존 사용자 활성 상태·역할·만료·권한을 검증하고, 토큰 원문 대신 해시만 트랜잭션 내부에 기록합니다. 요청 종료 시 이 값은 사라집니다.

명시된 업무 테이블의 쓰기 트리거가 해당 세션을 수집하고, 지연 제약 트리거가 커밋 직전에 세션 만료를 연장합니다. 따라서 저장이 롤백되면 연장도 롤백됩니다. 인증 행의 잠금을 업무 행 잠금 뒤에 잡아, 읽기·다중 탭 저장의 잠금 경합을 줄입니다.

기존 `touch_session` 호출은 호환성을 위해 유지하지만 조회 시 세션 행을 갱신하지 않습니다. `last_used_at`은 저장 활동을 기록하며, 기존 일부 저장 RPC의 명시적 기록도 유지됩니다. 감사 로그, 로그인 메타데이터, 외부 전송 상태의 백그라운드 갱신에는 쓰기 활동 트리거를 설치하지 않습니다.

새 업무 테이블이나 별도 서비스가 추가되면 인증된 쓰기가 같은 트랜잭션에서 이 수집 경로를 거치는지 확인해야 합니다. 외부 서비스가 별도 서비스 계정으로 기록한 내용은 개인 세션을 자동 연장하지 않습니다.

## 검증

`tools/check-login-session-db.ps1`은 마이그레이션과 기능 검증 후 모두 롤백합니다. `-Installed`는 배포된 함수를 검사하고 동시 조회·저장도 확인합니다. 동시성 검사에서만 임시 QA 계정·스펙을 잠시 커밋하고, 마지막에 해당 QA 자료와 감사 기록을 삭제합니다. 운영 거래·생산 자료는 커밋하지 않습니다.

브라우저 로그인 복원·오류 재시도 회귀 검증: `node tools/test-login-recovery.cjs`.
