# 제품스펙 월사용량과 등록 제품 연결

`product_spec_monthly_usage_catalog` 마이그레이션은 `product_specs.monthly_usage`와 `material_product_id`를 추가합니다. 기존 스펙은 두 값 모두 NULL로 유지하며 자동으로 이름을 맞추거나 제품을 추측해 연결하지 않습니다.

- 월사용량은 KG 단위 선택 입력, 0 이상 999,999,999 이하이며 소수 여섯 자리까지 허용합니다. 미입력은 NULL, 입력한 0은 숫자 0으로 보존합니다.
- 화면의 ‘월사용량 합계’는 현재 거래처·유통사·검색 조건에 해당하는 스펙만 대상으로 품목명(원재료명)과 원산지 조합별로 묶습니다. 이름과 원산지는 NFKC·대소문자·앞뒤 공백을 정규화해 비교하며, 부위·포장 문구나 원산지 별칭을 임의로 합치지 않습니다. 브랜드나 거래처를 별도 집계 키로 사용하지 않습니다.
- 합계는 1KG의 백만분의 일 단위 정수로 계산해 소수 덧셈 오차를 방지합니다. 미입력 건수는 별도로 표시하고 합계에서 제외합니다. 모든 값이 미입력이면 0으로 표시하지 않습니다.
- 상세 스펙 인쇄에는 월사용량 열을 포함하고, 합계표 인쇄는 품목·원산지·월사용량 합계만 출력합니다. 두 출력 모두 현재 검색·선택 조건을 표시하는 A4 세로 문서이며 단가 열은 제외합니다.

## 등록 제품 선택

원재료 검색은 기존 공용 품목 팝업을 `product-spec` 컨텍스트로 사용합니다. `labelProducts`에 등록된 활성 ‘제품’만 선택 가능하고 원료육 탭은 숨깁니다. 다른 메뉴의 팝업 유형 선택은 유지합니다. 제품명·품목코드·브랜드·원산지·포장규격으로 확인하며, 기존 5초 카탈로그 갱신도 그대로 적용됩니다.

선택하면 제품 이름과 원산지를 입력칸에 채우고 원산지는 수정할 수 있습니다. `material_product_id`는 등록 제품 ID 문자열을 저장하며, 이름이 같은 제품도 서로 다른 등록 ID로 연결합니다. 서버는 현재 카탈로그를 확인하고 저장할 제품명을 결정합니다.

과거 직접 입력한 스펙은 이름을 변경하지 않으면 월사용량 등 다른 내용을 수정할 수 있습니다. 새 스펙과 복사 등록에서는 제품을 선택해야 합니다. 이미 연결된 제품이 이후 중지·삭제되더라도 기존 연결과 이름을 유지한 스펙 수정은 허용하며, 새 등록이나 다른 제품으로 바꾸는 경우에는 활성 제품을 선택해야 합니다.

예전 탭의 API 요청이 새 필드를 생략하면 저장된 월사용량과 제품 연결을 보존합니다. 명시한 NULL은 월사용량을 비우는 의미입니다. 구버전 API의 신규 직접입력 요청은 호환을 위해 유지하지만 새 화면은 제품 선택을 확인합니다.

## 저장과 검증

기존 개인 세션·제품스펙 조회/등록/수정 권한과 revision 검사를 사용합니다. RLS와 직접 테이블 접근 차단을 유지하고, 수정 전후 값을 변경이력에 저장합니다. 기존 포장규격·유통 필드의 구버전 호환도 유지합니다.

`tools/check-product-spec-usage-db.ps1`은 새 설치와 가상 카탈로그·사용자·스펙을 검사한 뒤 모두 롤백합니다. 배포 후 `-Deployed`는 설치를 건너뛰고 동일한 검사를 롤백합니다. `tools/test-product-specs.cjs`는 실제 공용 검색 팝업·저장·복사·정렬·권한을, `tools/test-product-spec-print.cjs`는 선택 인쇄·월사용량 합계·원산지 분리·0/미입력·PDF 출력을 검사합니다.
